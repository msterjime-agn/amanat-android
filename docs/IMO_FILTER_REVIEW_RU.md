# Проверка фильтра IMO после сборки №6

Дата проверки исходников: 24.10.2026.

Проверенная база: `43ea2944806cf28e8561c718be7752b99e089c17` в
`msterjime-agn/amanat-android`. На момент проверки это также HEAD `main`.
[Сборка №6](https://github.com/msterjime-agn/amanat-android/actions/runs/40075655292)
завершилась успешно именно для этого коммита. Её тест проверяет разбор короткого
текста передачи, но не выбор группы в `ImoNotificationService.java`.

## Что делает сборка №6

После проверки разрешённого пакета IMO, переключателя сбора, категории звонка
и флага сводного уведомления сервис принимает сообщение, если выполняется хотя
бы одно условие:

```java
"Amanat".equalsIgnoreCase(title.trim())
"Amanat".equalsIgnoreCase(conversation.trim())
```

`EXTRA_TITLE` — общий заголовок уведомления; он может содержать имя отправителя.
`EXTRA_CONVERSATION_TITLE` — отдельное название беседы. Это разные поля.
`EXTRA_IS_GROUP_CONVERSATION` содержит признак групповой беседы, но сборка №6
его не проверяет.

Таблица показывает результаты для заданных полей, а не подтверждённые дампы
конкретной версии IMO на телефоне пользователя. `—` означает отсутствие поля.

| EXTRA_TITLE | EXTRA_CONVERSATION_TITLE | Признак группы | №6 | Исправление на Android 9+ |
|---|---|---|---|---|
| Agmet | Amanat | true | Принимает | Принимает |
| Amanat: Agmet | Amanat | true | Принимает | Принимает |
| Amanat | Family | true | Ошибочно принимает другую группу | Отклоняет |
| Amanat | — | false | Ошибочно принимает личный контакт | Отклоняет |
| Agmet | Amanat | false | Принимает именованную личную беседу | Отклоняет |
| Agmet | NBSP + Amanat + NBSP | true | Теряет: trim не удаляет NBSP | Принимает |
| Agmet | bidi-обрамление + Amanat | true | Теряет: trim не удаляет эти знаки | Принимает |
| Amanat | — | true | Принимает, хотя заголовок может быть именем отправителя | Отклоняет как неоднозначное |
| Amanat | — | — | Принимает без подтверждения группы | Отклоняет как неоднозначное |
| Amanat: Agmet | — | — | Отклоняет; сообщение нужной группы может потеряться | Отклоняет до подтверждения формата |

| Agmet | Аманат | true | Отклоняет: кириллица отличается от Amanat | Отклоняет |

Если название нужной группы находится только в `EXTRA_TITLE_BIG`, тексте,
сводке или нестандартном поле IMO, №6 не найдёт его. Само наличие слова Amanat
в тексте передачи не доказывает принадлежность чату.

## Минимальное исправление

1. Фильтр использует только отдельное название беседы. Общий заголовок больше
   не позволяет обойти ограничение, даже если он равен Amanat.
2. Совпадение — точное, без учёта регистра, после удаления пробелов и управляющих
   знаков направления по краям. NBSP и узкий NBSP поддержаны. Внутренние символы,
   кириллица, эмодзи, номера и суффиксы не удаляются.
3. Android 9 / API 28 и новее: требуется булев `true` в
   `EXTRA_IS_GROUP_CONVERSATION`. `false`, отсутствие и неверный тип отклоняются.
4. Android 8 / API 26–27: при отсутствии признака сохранено старое правило
   MessagingStyle — отдельное название беседы обозначает группу. Если признак
   передан как `false` или имеет неверный тип, уведомление отклоняется и здесь.
5. Проверки пакетов IMO, отключения сбора, звонков и групповых сводок сохранены.
   Извлечение текста и учёт передач не меняются.

Документация Android подтверждает различие названия и признака группы:
[Notification](https://developer.android.com/reference/android/app/Notification#EXTRA_IS_GROUP_CONVERSATION),
[MessagingStyle](https://developer.android.com/reference/android/app/Notification.MessagingStyle#isGroupConversation()).
Начиная с Android P возможны именованные негрупповые беседы.

Это намеренно строгий фильтр. Если установленная версия IMO показывает имя
группы только в общем заголовке, автоматический импорт таких уведомлений
останется недоступным. Поддержку нового формата следует добавлять после
проверки реальных полей уведомлений нужной группы и контрольного чужого чата.
Подстановка `contains("Amanat")` или поиск названия в тексте нарушит ограничение.

Имена групп не являются уникальными идентификаторами. Две разные группы с
одинаковым названием Amanat и одинаковыми признаками этим патчем не различаются.
Для такого случая потребуется отдельная привязка к устойчивому идентификатору
беседы, если IMO передаёт его, и выбор пользователем нужной группы. Номер
уведомления или Android groupKey сами по себе не считаются идентификатором чата.

## Автоматические проверки

В корне проекта при установленных Node.js и JDK 17:

```sh
node --test tests/*.test.mjs
```

Команда компилирует **рабочий Java-класс** фильтра и запускает 96 проверок:
точное имя, регистр, пробелы Unicode, bidi-обрамление, пустые поля, чужие имена,
ложный и отсутствующий признак группы, неверный тип признака, границу API 27/28.
Версии API 26, 27, 28 и 35 передаются как тестовые данные; это JVM-тесты,
а не запуски Android-эмуляторов. Вместе с прежними тестами учёта и короткого
сообщения получено 18 успешных тестов Node, без пропусков.

Workflow запускает ту же команду после установки JDK 17 и Node.js. Существующая
настройка запуска для ветки `fix/imo-group-metadata` сохранена: её изменения
запускают сборку APK и Android Lint до слияния. Эти проверки не подтверждают
доставку реальных уведомлений IMO.

## Проверка на Android

1. Используйте APK из успешной сборки ветки с исправлением, а не APK №6.
   Для ручного запуска: GitHub → Actions → Build Android APK → Run workflow →
   выбрать ветку исправления → скачать `Amanat-Android-APK` из Artifacts.
   При push в ветку `fix/imo-group-metadata` сборка запускается автоматически.
2. Перед заменой тестовой установки сохраните резервную копию карточек.
   Необработанные входящие в эту копию не входят. Если подписи тестовых APK
   различаются, обычное обновление поверх старого приложения невозможно.
3. В Аманат откройте «Ещё», предоставьте доступ «Аманат: входящие IMO» к
   уведомлениям и включите сбор. В самом IMO включите уведомления и показ текста
   группы Amanat. Сверните IMO: открытая переписка может не создавать уведомлений.
4. С другого аккаунта отправьте **новое** сообщение в нужную группу, например
   `AGN 1015: #901 Test Amanat 863000001 Daşoguz 1 $`.
   Убедитесь, что Android показал уведомление. Откройте раздел IMO в Аманат,
   нажмите «Обновить». Текст должен появиться на разбор; карточка сама не создаётся.
5. Отправьте контрольное сообщение с другим номером (#902) из другой группы.
   Затем отправьте #903 из личного чата, где контакт на тестовом телефоне
   называется Amanat. Эти сообщения не должны появиться во входящих Аманат.
   При возможности повторите с отправителем Amanat внутри другой группы.
6. Повторите доставку в нужную группу от двух разных отправителей и при
   нескольких непрочитанных чатах. Принимаются только подходящие дочерние
   уведомления группы; общая сводка IMO пропускается. Повторите при выключенном
   экране, затем с выключенным переключателем сбора — новые сообщения не должны
   добавляться. Для IMO HD проверку нужно выполнить отдельно, если он используется.
7. Откройте разбор #901 и проверьте получателя Test Amanat, телефон 863000001,
   город Daşoguz, сумму 1 USD. Это отдельная проверка парсера после фильтра.

Если шаг 4 не проходит, сначала установите, появилось ли само уведомление IMO.
При наличии уведомления можно подключить Android Platform Tools, оставить
уведомление в шторке и выполнить локально:

```sh
adb shell dumpsys notification --noredact > imo-notifications.txt
```

В записи нужного пакета проверьте `android.title`, `android.conversationTitle`,
`android.isGroupConversation`, категорию, flags и наличие текста. Сравните с
уведомлением из контрольного чужого чата. Не публикуйте полный дамп: он может
содержать сообщения других приложений. Для разбора достаточно выбранных полей
с заменёнными личными данными. Если название беседы или признак группы
отсутствуют на Android 9+, строгий отказ ожидаем; это не подтверждает поломку
разбора текста. Старые сообщения патч повторно не загружает и из базы не удаляет.

В существующем PR №1 до этого дополнения уже были изменены `applicationId`
на `tm.ashyrov.amanat.preview` и версия на 1.0.1 для отдельной тестовой установки.
Эти изменения сохранены; данное дополнение фильтра не меняет `app/build.gradle`.
Данные основной установки автоматически в отдельную тестовую установку не
переносятся.

Фактическая доставка на телефоне пользователя пока не проверена.
